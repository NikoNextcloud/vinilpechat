# Винил & Брезенти – GitHub + Vercel + Supabase

Самостоятелен сайт на български с **40 продукта, 8 категории, каталог, количка за заявки, администрация за цени, снимки и поръчки**. Конфигурацията за Vercel използва Supabase за постоянно съхранение; GitHub пази кода. Плащания с карта не са включени – изпращат се заявки.

## Архитектура

- **GitHub** – код и версии. Не се използва за жива база данни и не изпълнява сървърния код.
- **Vercel** – статичните файлове от `public/` и Node serverless API в `api/`.
- **Supabase PostgreSQL** – продукти, продажни и доставни цени (в отделни таблици), настройки, заявки.
- **Supabase Storage** – снимки, качени от администратора. Може да използвате и локални файлове в `public/products/` след изрично разрешение за правата им.
- **Supabase Auth** – акаунт на собственика; само имейлът, посочен в `ADMIN_EMAIL`, може да управлява магазина. Няма свободно администраторско регистриране.

## 1. GitHub

Създайте **ново private** хранилище `vinil-brezenti-shop` в GitHub. Качете файловете от корена на този ZIP без външната директория. Не добавяйте `.env` с реални ключове; `.gitignore` ги изключва.

**Внимание:** репозиторият не е създаден автоматично – това е подготвен пакет за импорт. Не презаписвайте съществуващия `vinilpechat` проект.

## 2. Собствен Supabase проект

В [Supabase Dashboard](https://supabase.com/dashboard) създайте отделен проект (не използвайте случайна съществуваща база). Отворете **SQL Editor** и изпълнете в този ред:

1. `supabase/migrations/001_vinyl_store.sql` – таблици, ограничения, RLS и Storage bucket.
2. `supabase/seeds/002_catalog.sql` – 8 категории, 40 продукта, цени и настройки.

Кодът използва таблици с префикс `vinyl_` и не променя съществуващите таблици с други имена. Seed скриптът е идемпотентен (повторно изпълнение не изтрива редакции по цените).

В Supabase отворете **Authentication → Users**, добавете и потвърдете вашия администраторски имейл. След това във Vercel задайте същия `ADMIN_EMAIL`. Не публикувайте администраторски пароли в GitHub.

## 3. Vercel

1. Във Vercel изберете `Add New → Project → Import Git Repository` и свържете новото GitHub хранилище.
2. Framework: `Other` / **No Framework**. Root Directory: `/`. Файловете в `public/` ще се обслужват статично, а `api/` – от Vercel Functions.
3. Добавете променливите от `.env.example` в `Settings → Environment Variables` (стойностите ги вземете от вашия Supabase проект):
   - `SUPABASE_URL`
   - `SUPABASE_ANON_KEY` (или legacy anon JWT key от `Project Settings → API Keys`)
   - `SUPABASE_SERVICE_ROLE_KEY` (**тайна, само за сървъра**)
   - `ADMIN_EMAIL`
   - `SESSION_SECRET` (поне 32 случайни символа)
4. След конфигуриране отворете `/api/health` и `/api/catalog`, после `/` и `/#admin`. Входът изисква създаден и потвърден потребител в Supabase Auth.
5. Използвайте URL от Vercel за сайта; **GitHub сам по себе си не е хостинг за този API**.

За пример на локална проверка на каталога отворете `public/index.html`. Ако няма свързан Supabase, виждате само **демо каталог** и изпратените заявки не стигат до вас. Цените в реалния магазин се четат от Supabase, не от GitHub.

## 4. Снимки и вариации

Снимките на доставчика не са включени в ZIP: изтеглянето им в предишната среда е било неуспешно. **Не твърдим, че продуктите имат 131 локални изображения**. При разрешение за използване на фотографиите стартирайте `python3 scripts/download_supplier_media.py`, после `python3 create_seed.py`, прегледайте `public/products/` и данните за опциите в `data/seed.json`, и качете новата версия в GitHub. За вече създаден Supabase каталог прикачете снимките през `/#admin` (Supabase Storage) или направете отделен проверен импорт. Цените за опциите не се изчисляват автоматично – потвърждавайте ги.

## 5. Важни ограничения преди публично пускане

- **Не публикувайте магазин с чужди снимки, ако нямате право за търговска употреба.** Само публично достъпна снимка не означава свободен лиценз.
- Попълнете фирмени данни, общи условия, поверителност, контакти, доставка и право на отказ.
- Не всички варианти и техните конкретни цени са потвърдени.
- Кошницата създава **заявка**, не финално платена поръчка; няма имейл известия, плащания с карта, ERP или куриерска интеграция.
- Защита против спам/ботове и лимити на заявките трябва да се добавят, преди да приемате голям публичен трафик.
- Администраторският вход използва само **потвърден** Supabase акаунт с адрес, равен на `ADMIN_EMAIL` във Vercel. Сесията е кратка и при изтичане е необходим повторен вход.

## Структура

- `public/index.html`, `public/site.js`, `public/site.css` – магазинът.
- `api/` – Supabase API за Vercel и проверка на администраторския достъп.
- `supabase/migrations`, `supabase/seeds` – SQL за проекта.
- `data/seed.json`, `create_seed.py`, `scripts/download_supplier_media.py` – входен каталог и помощен импортер.
- `server.js` – старият локален файл-базиран режим (само за локални тестове; **не се използва във Vercel**).

`npm test` изпълнява синтактична проверка и структурни тестове за каталога и SQL seed. Не замества реален тест в работещия Vercel/Supabase проект.
